1. 앱 소개 및 개발 목적 / Project Overview

1.1 앱을 한 문장으로 소개 / One-sentence description

StudyMate is an Android app that helps one university student keep assignments, due dates, completion status, and exam details together, then see what is still unfinished.

1.2 해결하려는 문제 / Problem to solve

During a semester, due dates and exam details are easy to lose, because one assignment may sit in a notebook, another in a chat message, and an exam room may be remembered only from a slide. When those notes stay separate, nothing shows the unfinished work and the next exam together, so a deadline can pass without a clear reminder.

StudyMate brings the assignment and the exam into one app on the student’s own phone. The student adds the work, sees it in a list, marks it completed when it is finished, and keeps the exam date, time, and location beside the coursework. The phone stores each row locally, so the same lists are still there the next time the app opens.

1.3 대상 사용자 및 이용 상황 / Target users and use cases

The target user is a university student who takes several courses and wants one simple place on their own phone for coursework and upcoming deadlines. The first version stores every row in a Room database on that phone, and sharing lists with classmates can wait for a later version if there is time in the final project.

  • After class, the student adds an assignment with its subject, due date, and priority.
  • In the morning, the student opens the dashboard to see how many assignments are pending and which deadlines are closest.
  • When the work is finished, the student marks that assignment completed. The list and the counts update.
  • Before exam week, the student checks the exam screen for the subject, date, time, and room.

Planned scope for a student project

This midterm is the plan, and the final-term project will continue from it. The app stays at four screens, two database tables, and the five features in the next section, which is a realistic size for one student who has studied Kotlin, Fragments, Navigation, RecyclerView, Room, and Git.

2. 주요 기능 정의 / Core Features

Five features are planned. Each one names what the student does, what should happen, and which Android topic will be used.

No. 기능명 / Feature 사용자 동작·기대 결과 / User action and result Android 기술 / Technology
1 Add and edit an assignment The student taps Add, or Edit on an existing row, fills in the title, subject, description, due date, and priority, then taps Save. The assignment is stored on the phone and shown in the list. AssignmentFormFragment, Navigation, Room
2 Show assignments in a list The student opens the assignment screen and scrolls. Each row shows the title, subject, due date, priority, and whether it is pending or completed. Filter buttons show All, Pending, or Completed. RecyclerView, Adapter, AssignmentListFragment
3 Mark completed or delete The student taps Complete on a pending row, or taps Delete and confirms. The status changes, or the row is removed. The list and the dashboard counts update. Room update and delete, RecyclerView
4 Manage exam schedules The student enters a subject, date, time, and location, then taps Save. The exam appears in the list. Edit and Delete change or remove that exam. ExamScheduleFragment, RecyclerView, Room
5 Dashboard summary The student opens the app and lands on the dashboard. It shows the number of pending assignments, the number of completed assignments, and a short list of upcoming deadlines and the next exam. DashboardFragment, Room queries, RecyclerView

2.1 가장 중요한 기능 및 이유 / Most important feature and why

The most important feature is saving an assignment and seeing it again with its due date, because that is the question a student is trying to answer when the app opens: what work is left, and when is it due? Once that path works, marking an item completed, updating the dashboard counts, and showing the exam list all follow the same pattern of writing one row on the phone and reading it back onto the screen. The size is realistic for the final project, since the form collects the title, subject, description, due date, and priority, Room stores that row, and RecyclerView shows it. The title, subject, and due date must be filled in before Save, because an empty title would make the list hard to read.

2.2 RecyclerView 사용 계획 / List display plan

RecyclerView is how the list screens show rows from the database. The Adapter keeps one row layout and fills it for each item, and while the student scrolls, rows that leave the screen can be reused so a longer semester list stays comfortable to read.

  • AssignmentListFragment is the main list. Each row brings together the title, subject, due date, priority (High, Normal, or Low), and the status Pending or Completed, along with Complete, Edit, and Delete. The filter buttons show All, Pending, or Completed, where pending means isCompleted = 0 and completed means isCompleted = 1.
  • ExamScheduleFragment uses the same kind of list for exams, so each row shows the subject, exam date, exam time, and location, with Edit and Delete.
  • DashboardFragment uses a shorter RecyclerView for the nearest pending assignments, sorted by due date, together with the next exam. When there are no rows yet, the screen shows “No assignments yet.”

4. 화면 이동 흐름 / Navigation Flow

The Navigation Component will connect the four fragments. DashboardFragment is the start destination. A bottom navigation bar moves among the dashboard, the assignment list, and the exam schedule. The assignment form is opened from the list, then returns to the list.

DashboardFragment Start screen. Bottom navigation also jumps among Dashboard, Assignments, and Exams.
1. Tap Assignments
AssignmentListFragment Full list, filters, Complete, Edit, Delete
2. Tap Add or Edit
AssignmentFormFragment Empty form for Add. Edit passes assignmentId.
3. Save or Cancel returns to the list
1. Tap Exams
ExamScheduleFragment Form and exam list on the same screen
Save, Edit, and Delete stay on this screen and refresh the exam list. This screen does not open the assignment form.

화면 이동 설명 / Explain the transitions

  1. App open → DashboardFragment. The student sees pending and completed counts, upcoming assignment deadlines, and the next exam.
  2. Dashboard → AssignmentListFragment. The student taps Assignments in the bottom navigation, or the assignments shortcut on the dashboard.
  3. AssignmentListFragment → AssignmentFormFragment. Add opens a blank form. Edit passes the assignment id and fills the form with that row.
  4. AssignmentFormFragment → AssignmentListFragment. Save writes the row and returns to the list. Cancel returns without writing. The system Back button does the same job as Cancel.
  5. Dashboard or bottom nav → ExamScheduleFragment. The student views the exam list and uses the form on that screen to add or edit an exam. Save stays on this screen and refreshes the list.
  6. Bottom navigation can move directly among Dashboard, Assignments, and Exams. From the form, the student returns to the list first.
The navigation graph will contain these four fragments and the actions above. Passing assignmentId is the only argument in the first version. Add opens a blank form and sends no id. Edit sends the id so the form can load that row.

Why the screens are connected this way

The dashboard is the start screen because the first thing a student needs is a summary rather than an empty form, so the assignment form stays off the bottom bar and opens only from Add or Edit. Save or Cancel then returns to the list the student was already using. An exam has only four fields, so its form stays on ExamScheduleFragment above the exam list, while an assignment has more fields and therefore uses its own AssignmentFormFragment. The system Back button on that form returns to the list without saving, which matches Cancel, and the bottom navigation switches only among Dashboard, Assignments, and Exams.

5. Room SQLite 데이터베이스 설계 / Database Design

All of the student’s coursework stays on the phone in one local SQLite database, and Room creates that file the first time the app opens the database. Two tables are enough, because assignments and exams are two different lists: one table holds the coursework, and the other holds the exam date, time, and place. A third table is not part of this version, since the app does not store accounts or a separate subject list.

DB 이름 / Database name: studymate_database

테이블 이름 / Table 1 name: assignments

컬럼명 / Column 타입 / Type 키·제약 / Key 설명 / Description
assignmentId INTEGER PK, auto-generated Unique number for one assignment. The student does not type this.
title TEXT NOT NULL Assignment name shown in the list.
subject TEXT NOT NULL Course or subject name.
description TEXT Optional notes about the work.
dueDate TEXT NOT NULL Due date stored as text, such as 2026-11-12, so it can be sorted.
priority TEXT NOT NULL High, Normal, or Low.
isCompleted INTEGER NOT NULL 0 = pending, 1 = completed. SQLite has no boolean type, so a number is used.

Example record (a sample of one future row, not data from a running app):

assignmentId=1, title=Lab report, subject=Computer Science, description=Write up the week 9 lab, dueDate=2026-11-12, priority=High, isCompleted=0

6. Room 및 데이터 처리 계획 / Room & Data Operations

Room helps the app store rows in a SQLite file on the phone. The classes below describe the tables and the actions. Room creates the file and does the saving and loading.

구성 요소 / Component 예정 역할 / Planned responsibility
Entity An Entity is the Kotlin class for one table. Assignment has the same fields as assignments, and Exam matches exams. One object is one row. The id is the primary key, and Room fills it in for a new row.
DAO A DAO is the set of actions for one table. AssignmentDao can insert, update, delete, and read assignments, and it can set isCompleted. ExamDao does the same jobs for exams. The fragment calls these functions, and Room prepares the SQL.
AppDatabase StudyMateDatabase is the Room database class. It connects both entities to both DAOs and stores them in the local file studymate_database. The app asks this class for a DAO when it needs to save or read.
Repository (optional) The first version calls the DAO from the fragment. A repository can be added later if several screens share the same save or load code.
Fragment The form collects input. The lists show rows. The dashboard shows counts and the nearest dates. After a change, the screen reads the table again.

데이터 처리 흐름 / Data flow: When the student taps Save, the form first checks that the title, subject, and due date are filled in, and then AssignmentDao inserts a new row or updates the existing one in the assignments table. The list asks the DAO for those rows, and the Adapter places them in the RecyclerView, so the student sees the saved work immediately. Tapping Complete changes isCompleted from 0 to 1, while Delete removes the row only after the student confirms. Exams follow that same path through ExamDao, and the dashboard counts the pending and completed rows and reads the nearest due dates. Room keeps the SQLite file on the phone, so closing the app leaves the lists in place and the next launch shows the same rows.
